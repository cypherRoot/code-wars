## Why it matters

Almost every query a data engineer writes has a `WHERE`. You use it to process only yesterday's data, drop test accounts, or skip cancelled orders. Getting a filter subtly wrong is also how most "the numbers don't match" bugs start, so this lesson includes the classic traps.

<JsBridge>

```js
customers.filter(c => c.country === "India")
```

```sql
SELECT *
FROM customers
WHERE country = 'India';
```

<Breaks>
JavaScript's `===` returns `true` or `false`. SQL logic has **three** values: true, false and *unknown*. Unknown is what you get whenever NULL is involved, and `WHERE` only keeps rows where the condition is **true**. Also: SQL uses a single `=` for comparison, and `AND` / `OR` / `NOT` instead of `&&` / `||` / `!`.
</Breaks>

## The NULL trap

NULL isn't zero or an empty string. It means **unknown / missing**. Make a prediction:

<Worked id="null-trap" />

| Expression | Result |
|---|---|
| `NULL = NULL` | unknown |
| `NULL <> 'London'` | unknown |
| `city IS NULL` | true / false: **use this** |
| `city IS NOT NULL` | true / false |
